## 실제 브라우저 스모크

내장 브라우저로 데이터 입력/탐색을 확인하고, Chrome으로 시각 검수 및 모바일 390×844 반응형을 확인했다. 사용한 `[샘플]` 프로젝트/제품은 합성 데이터이며 실제 브랜드/파일/크리에이터를 주장하지 않는다.

- 비로그인 프로젝트 URL → 로그인 화면. 관리자 로그인 후 DB 수치 표시.
- `[샘플] 리플러츠` 생성, 브랜드/USP/스타일 입력, 제품 저장, 새로고침 후 유지.
- 일본/TikTok과 미국·캐나다/Instagram·YouTube 캠페인 각각 생성. 다른 팔로워 범위/목표, 수정 후 타겟팅 독립 유지.
- 최대 팔로워가 최소보다 작은 요청 거절. 오류 후 입력과 체크박스 유지.
- 브랜드 원본 수정 후 기존 캠페인의 생성 시점 소개/제품 정보 유지.
- `[샘플] 베베도르`에 리플러츠 제품이 나타나지 않음.
- 프로젝트 카드 집계 오류를 수정하고 통합 테스트로 재발 방지.
- 모바일 표의 가로 넘침 원인(스크린리더 텍스트의 절대 위치)을 수정. viewport 390에서 document scrollWidth 375로 문서 가로 넘침 없음. 표 내부는 가로 스크롤.
- 후속 메뉴는 비활성화. 실제 SNS 탐색/이메일 발송을 실행하지 않음.

캡처는 로컬 `.local/qa/`에 보관하며 Git에서 제외한다. Playwright 회귀 테스트 2건은 `tests/browser/`에 작성했다.

[검증 실행 39540706755](https://github.com/kimue7057/ERUTY-Creator-Seeding-OS/actions/runs/39540706755)에서 기능 코드 `faf30b9`의 설치/마이그레이션/시드/타입/린트/단위 4건/DB 통합 4건/빌드/**Playwright 2건 전체 통과**를 확인했다. Linux CI는 임시 PostgreSQL 18 서비스와 Chromium을 사용했다.

브라우저 회귀는 비로그인 리다이렉트·로그인 오류와 프로젝트/제품 생성·브랜드 수정·캠페인 독립 타겟팅·다중 선택·검증 오류 후 값 유지·브리프 보존·프로젝트 분리·모바일 넘침을 검사한다. 최초 실행에서 모바일에 숨겨진 예정 메뉴를 조회하던 테스트의 확인 순서를 수정한 후 재실행에 통과했다.

## projects-02 후속 검증 (2026-10-21)

[Draft PR #4](https://github.com/kimue7057/ERUTY-Creator-Seeding-OS/pull/4), [CI 실행 39545628423](https://github.com/kimue7057/ERUTY-Creator-Seeding-OS/actions/runs/39545628423), 기능 코드 `4ed8ea7`: 타입/린트/단위 **5건**/실제 PostgreSQL·S3 통합 **11건**/빌드/Chromium 브라우저 **4건** 전부 통과했다. 실제 SeaweedFS 4.48 S3에 PDF/JPG/PNG/WebP/MP4를 업로드·재조회·다운로드하고 SHA-256 일치를 확인했다.
