# ERUTY 로컬 PC 운영 안내

2026-10-26 사용자 결정: 상시 서버 전환은 보류하고 우선 이 PC를 켜둔다. 새 임시 OAuth 주소 복구는 별도로 승인했다. 성공한 크리에이터·근거·제출 run을 보존하고 추가 발굴·저장 실증은 반복하지 않는다.

복구 결과: 서버의 새 issuer/JWKS와 기존 Probe/Discovery Tunnel 준비 상태를 확인했다. 기존 ChatGPT 연결은 옛 인증 주소를 사용하고 현재 관리 화면에 OAuth 주소 편집 항목이 없어 보존했으며, 같은 Tunnel에 새 비공개 연결을 추가했다. 사용자의 로그인·동의 후 새 연결의 Primary 계정과 OAuth 표시를 확인했다. 실제 업무 도구를 다시 호출하지 않았다. 읽기 전용 진단에서 기존 DB grant는 모두 만료되고 새 환경과 일치하지 않음을 확인했다. 조회·저장을 재개하려면 운영 권한 수명·승인 정책을 별도로 정해야 하며, 반복 grant 재발급을 연결 안정화 완료로 간주하지 않는다.

후속 구현: [최대 7일 관리자 운영 승인](DISCOVERY-OPERATING-APPROVALS.md)을 별도 opt-in 경로로 준비했다. 기본값은 꺼짐이며 실제 적용·승인 발급은 아직 수행하지 않았다. OAuth 토큰 만료, 운영 승인 만료, Work/SNS 실증 Gate를 각각 유지한다. 기존 성공 보고와 읽기 전용 DB 대조는 일치했으며 추가 SNS 방문·관찰 저장을 반복하지 않았다.

## 계속 사용하는 동안

- PC 전원, 외부 전원 연결, 인터넷, Docker Desktop을 유지한다. 모니터만 끄거나 Windows를 잠그는 것은 가능하다. 절전·최대 절전·로그아웃·Docker 종료는 피한다.
- 현재 전원 연결 시 자동 절전과 최대 절전은 모두 사용 안 함이다. 배터리 사용 시 자동 절전은 10분이므로 전원을 분리하지 않는다.
- Windows 업데이트·정전·재부팅·네트워크 장애로 중단될 수 있다. 로컬 PC 운영을 무중단 서버로 간주하지 않는다.
- 임시 OAuth Tunnel은 실행 중인 프로세스를 유지해야 한다. 프로세스가 종료된 뒤 새로 만들면 주소가 바뀔 수 있다. 감독 작업은 임의로 주소를 바꾸거나 grant를 갱신하지 않는다.

## 껐다가 다시 시작했을 때

1. Windows에 원래 사용자로 로그인하고 바탕화면 **ERUTY 서버 시작**을 실행한다. 기존 Docker 엔진과 대시보드·MCP 감독 작업을 요청한다.
2. [로컬 대시보드](http://127.0.0.1:3001)에 접속한다. 로그인 화면 HTTP 200은 웹 서버 정상 응답이며 사용자 로그인 성공을 의미하지는 않는다.
3. Work 연결이 실패하면 공개 OAuth 주소와 Tunnel 상태를 따로 확인한다. 시작 아이콘은 새 OAuth 주소 발급·Keycloak 변경·플러그인 재등록을 하지 않는다. 사라진 주소는 운영자가 승인된 절차로 서버와 클라이언트 설정을 함께 맞춰야 한다.
4. 만료된 OAuth 로그인과 DB grant는 별개다. 사용이 끝난 초기 실증 허가나 철회·만료된 grant를 재활성화하지 않는다. 실제 다음 작업의 최소 권한을 따로 확인한다.

Docker 오류 시 데이터 초기화·volume 삭제·무작정 재설치를 하지 않는다. 현재 전용 런처는 설치된 공식 Docker CLI와 frontend를 사용한다. Docker 업데이트가 기본 바로가기를 덮어쓰면 전용 런처를 확인한다. 완전 재부팅 후 자동 복구는 아직 검증하지 않았다.

## 읽기 전용 상태 확인

현재 checkout의 PowerShell 7에서 실행한다. 실행 정책을 우회하지 않는다.

```powershell
docker desktop status
docker ps --filter name=eruty --format '{{.Names}} {{.Status}}'
Get-ScheduledTask -TaskName 'ERUTY-*' | Select-Object TaskName, State
Get-Content .local/mcp-local-e2e/supervisor-status.json
```

`ready`는 로컬 Tunnel 준비 상태다. 실제 hosted Work 도구 실행 성공이나 유효한 DB 권한을 대신하지 않는다. 이번 복구에서는 크리에이터 관찰·제출 테스트를 다시 호출하지 않는다.

## 보존과 추후 전환

DB 덤프·role/권한 백업·기존 구성은 Git에서 제외한 비공개 실행 기록에 보관한다. DB 밖의 파일은 별도 백업 대상이다. 복구했다고 보고하려면 복원 검증을 별도 격리 대상에서 해야 한다.

[상시 서버 전환 계획](ALWAYS-ON-MIGRATION.md)은 나중에 재사용한다. AWS 로그인과 리소스 생성은 현재 진행하지 않는다. 다른 프로젝트의 AWS 리소스는 변경하지 않았다.
