# 선정 이후 연락·회신 관리

사용자 요청으로 STEP 6 범위를 확장한다. 발굴·평가·최종 선정 및 최초 제안의 근거·확인 절차는 유지한다.

## 흐름

1. 캠페인 선정 명단 → 연락하기: 분석, 문안, 템플릿/DM 미리보기, 회사 발신 계정·주소 확인 후 실제 발송.
2. 확인된 발송만 ‘연락한 크리에이터’에 자동 표시. 초안/실패/결과 불명 최초 발송은 기존 초안·발송 기록에서 확인한다. 기존 프로젝트·단독 발송은 기존 이력으로 표시하며 최종 선정을 만들지 않는다.
3. 채널·프로젝트/캠페인·발신 계정·담당·회신 필요 필터 → 원본 대화 읽기 → 고정된 회사 계정·수신자로 회신 → 접수 결과 보존. 새 메시지가 도착하면 전송 확인을 다시 받는다. 접수는 읽음 확인이 아니다.
4. 협업 상태, 담당자, 다음 연락일, 내부 메모를 별도로 저장한다. 보류/종료/진행 안 함 또는 보관된 캠페인은 회신을 막는다. 메모의 별도 편집 버전으로 동시 수정 손실을 막는다.

## 실제 연결

- Instagram 첫 제안은 기존 회사 Chrome 실행기 0.1.12를 사용한다. 받은 대화 조회와 회신은 검증된 회사 Meta 대화 API를 사용하며 마지막 실제 수신 24시간 이내만 허용한다. 확장 프로그램 업데이트는 필요 없다.
- 이메일은 기존 gmail.send에 gmail.readonly 동의가 추가로 필요하다. 발신 계정에서 ‘이메일 답장 수신도 연결 → 다시 로그인 · 권한 변경’. 읽기 권한은 메일함 전체에 적용되지만 ERUTY는 실제 발송한 메시지 ID에서 시작한 연락 대화만 조회·저장한다. 승인 실패는 기존 발송 연결을 지우지 않는다.
- Gmail은 기존 provider message/thread ID와 실제 참여자·발신 주소·검증된 별칭을 확인한다. 기존 threadId와 실제 In-Reply-To/References를 사용해 회신한다. 추가 참여자, 바뀐 상대 주소, 별도 Reply-To는 자동 승인하지 않는다.
- 활성 화면을 열면 조회하고 1분마다 제한된 묶음을 순서대로 조회한다. 수동 새로고침도 제공한다. **모든 화면을 닫은 상태의 상시 수신·푸시 알림, Meta Webhook, Google PubSub는 포함하지 않는다.** 조회 실패는 ‘답장 없음’으로 표시하지 않는다.
- 연결 테스트 메일은 ‘연결 테스트 포함’ 필터로 확인한다. 테스트를 위해 실제 크리에이터/평가를 만들어내지 않는다.
- 하나의 Instagram 대화에 여러 캠페인이 연결되면 원본 대화를 공유하고 현재 연락 건에 회신을 기록한다. 수신 메시지의 캠페인을 추측하지 않는다.
- 최신 500개 연락 건, 대화별 최신 200개 저장 메시지를 표시한다. Instagram API 동기화는 최근 20개 메시지로 제한되므로 과거 전체 보관을 보장하지 않는다. 첨부는 원본 SNS/메일함에서 확인한다.

## 설치·데이터 보호

DB 소유자로 0026_contact_crm.sql 및 scripts/outreach-grants.sql을 적용한다. 런타임은 기존 제한 역할을 유지한다. 기존 발송 자료는 변경하지 않고 확인된 기록을 새 테이블로 멱등 투영한다. 원본 메시지·회신 승인 기록은 트리거로 보호한다.

외부 전송 전 시도를 먼저 커밋하고 동일 대화의 처리 중/결과 불명은 새 ID도 차단한다. 네트워크/저장 실패 후 성공을 추측하거나 자동 재전송하지 않는다. 현재 DB 멤버 권한·조직·실제 계정·수신자·최신 대화 버전을 확인하고 인증 정보는 서버에만 둔다.

## 검증

typecheck/lint/unit/build, 폐기형 PostgreSQL의 contact-crm/instagram-dm/outreach 통합 테스트, 선정 → 연락 관리 → 수신 → 서버 회신 → 접수 기록 → 재접속/메모 보존 Playwright 흐름을 확인한다. UI는 320/390/1440에서 검사한다. 공급자 고정 응답은 합성 검증이며 실제 외부 전달과 구분한다.

운영 왕복 테스트는 허가된 회사/본인 계정만 사용하며 비공개 증거를 남긴다. 읽기 권한 동의나 새 수신이 없으면 실제 회신 검증을 완료했다고 보고하지 않는다.
