# 발굴 브라우저를 재사용하는 Instagram 첫 연락

사용자가 확정한 회사 계정·크리에이터·본문을 받아 Instagram의 실제 프로필/메시지 화면에서 DM을 보내는 경로다. 기존 발굴 스킬은 조회·저장 전용으로 유지하고, 같은 실행기에 별도 연락 작업을 추가한다. 공식 API의 기존 대화 회신과 구분한다.

## 사용자 흐름

캠페인 선정 명단 → 연락하기 → 분석 → 문장·템플릿 → 발신 계정/수신 프로필/본문 확인 → **첫 협업 제안 · 브라우저에서 직접 DM** → 실제 발송 확인란 → 요청 저장 → 실행기가 실제 화면 확인·전송 → 결과 표시.

직접 작성·연결 테스트는 **Instagram 첫 연락**(`/outreach/instagram/new`)에서 회사 계정·수신 아이디·텍스트를 명시해 1건씩 요청한다. 이 화면에서 보내도 캠페인 평가·선정 기록은 바꾸지 않는다. 캠페인 협업 제안에는 선정 명단의 분석·문장 단계를 사용하는 것이 기본 흐름이다. 기존 `/outreach/instagram`은 API 대화 조회·회신 화면으로 유지한다.

API 앱 토큰을 사용해 전송하는 경로가 아니다. 서버에는 등록한 회사 아이디가 있어야 하며 실제 브라우저에서 로그인 계정이 일치해야 한다. 계정이 ERUTY에서 연결 해제된 상태면 보낼 수 없다. 수신자의 선행 DM은 요구하지 않지만 Instagram의 실제 메시지 요청·계정 제한·로그인·CAPTCHA를 존중한다. 전송 불가·계정 불일치이면 중단하며 대체 계정이나 다른 접속 방식으로 회피하지 않는다.

## 실행기와 설치

기존 `scripts/codex-discovery-worker.ts`가 같은 브라우저 연결을 사용한다. 실행 PC와 Codex·회사 Instagram 브라우저가 켜져 있어야 하며, Vercel 서버만으로 사용자의 로컬 브라우저를 조작하지 않는다. 발굴과 연락은 동시에 브라우저를 움직이지 않는다. 연락 요청은 현재 작업이 끝난 뒤 우선 확인한다. 1시간 안에 시작하지 못한 요청은 중단하며 자동 재시도하지 않는다.

1. 소유자 DB로 `0020_browser_outreach`와 `scripts/outreach-grants.sql` 적용. 기존 연락·발굴 데이터를 수정하지 않는다.
2. 현재 로컬 실행기 설정 `.local/discovery/codex-browser/worker.config.private.json`에 `outreach_enabled:true` 추가. 기본값 false로 이전 실행기에 연락 권한을 자동 부여하지 않는다.
3. 이 저장소의 `skills/eruty-browser-outreach/SKILL.md`를 실행 PC의 Codex 스킬 폴더에 설치한다. 실행 프롬프트도 저장소의 같은 지침을 읽는다.
4. 기존 실행기를 다시 시작해 실제 브라우저 준비 검사를 통과시킨다. 서버 `CODEX_AUTOMATIC_DISCOVERY_ENABLED=true`와 기존 비공개 대시보드 연결은 그대로 사용한다. 새로운 SNS 비밀번호·DB 인증 파일을 실행기에 추가하지 않는다.

연락 가능한 실행기가 최근 45초 안에 준비 상태를 보고해야 요청을 받는다. 화면은 실행기·요청 상태를 10초마다 갱신한다. 준비 검사나 실제 계정 확인이 실패하면 미연결/중단으로 표시하며 활성화만으로 성공을 주장하지 않는다.

## 한 건의 발송 권한과 결과

`queued → preparing → armed → sent/unknown`, 전송 전에는 `blocked/cancelled`로 종료할 수 있다. 사용자 확인 후 발신/수신/본문·초안 revision을 불변 기록으로 남긴다. 조직·현재 멤버십·실행기 인스턴스·비공개 claim 토큰을 검증한다. claim은 10분이며 한 번만 할당한다. 스킬은 context로 정확한 작업을 읽고 브라우저에서 확인한 발신자·수신자·입력 문장·원본 화면 텍스트를 보낸다. `arm`은 캠페인 선정·초안·회사 아이디를 재검사하고 2분 동안의 1회 전송 허용을 반환한다. 같은 arm 요청을 다시 실행해 새로운 허용을 받을 수 없다.

arm 전에 요청 취소가 가능하다. arm 후 전송 결과를 확인하지 못하면 unknown으로 보존하고 같은 회사→상대의 새 요청과 API 경로도 차단한다. 완료 화면을 다시 불러와도 전송을 반복하지 않는다. 연결 끊김·실행기 종료 후에는 전송하지 않았다고 추측해 초기화하지 않는다. 앱에서 불명 결과를 자동 해제하는 기능은 없다.

`sent`는 실행기가 같은 수신자의 화면에 정확한 보낸 문장이 나타난 것을 관찰했다는 뜻이다. Meta API 메시지 ID·상대 수신·읽음을 증명하는 상태가 아니다. 화면 관찰 원본과 해시는 조직 범위의 발송 기록에 저장하며, 운영 로그에는 계정 비밀번호·토큰·메시지 원문을 남기지 않는다. 브라우저 클릭 자체는 성공으로 처리하지 않는다. 합성 브라우저/서버 테스트와 실제 Instagram 전송 결과는 별도로 기록한다.

이 기능은 한 건씩 명시한 첫 연락용이다. 대량 발송, 계정 순환, 메시지 제한 우회, 팔로우·좋아요·댓글, 계약·결제 약속은 연락 작업에 포함하지 않는다.
