# 시딩 업무 흐름과 메뉴

2026-11-12 사용자 승인 범위: 기존 발굴·평가·선정과 발송·회신 기능을 하나의 업무 흐름으로 연결한다. STEP 1–5의 판정·근거·템플릿 원칙과 실제 발송 확인 절차는 유지한다.

## 사용 순서

1. **브랜드·제품**: 프로젝트별 소개·제품·자료를 준비한다. 프로젝트는 기존 데이터 단위를 유지한다.
2. **캠페인**: 발굴·평가 → 후보 검토 → 최종 선정 → 제안 작성·발송 → 답장·협업으로 진행한다. 발굴 이력은 ‘발굴·평가 기록’에 있다.
3. **선정 명단 → 연락하기**: 크리에이터 분석, 제안 문장, 템플릿·미리보기, 발신 계정·주소·발송의 네 단계를 유지한다. 저장한 단계는 다른 기기에서도 복원한다. Instagram 첫 연락은 연결된 회사 Chrome 실행기로 전달하며 API/브라우저를 사용자가 고르지 않는다. 기존 API 초안은 기존 수신 대화 경로를 보존한다. TikTok 실제 전송은 준비 중으로 채널 선택 단계부터 알린다.
4. **연락·협업**: 작성 중인 제안, 발송 기록, 받은 답장·협의 진행을 연결한다. 캠페인 안의 연락·협업은 같은 자료를 해당 캠페인으로 좁힌 화면이다. 발송 후 동일 연락 건에서 채널별 대화와 결과를 확인한다.
5. **오늘 할 일**: 검토, 선정 후 제안 준비, 작성 중, 회신 필요, 다음 연락일, 수신 점검을 업무별로 연다. 집계 범위는 화면에 명시한다.
6. **설정**: 발신 계정, 템플릿·회사 서명, 회사 Chrome, 서비스 앱 설정을 모은다.

이전 프로젝트 문안·단독 수신자 발송·원본 Instagram 받은편지함은 ‘연락·협업 → 작성 중인 제안 → 이전 도구·기록’에서 접근한다. 새 업무의 기본 진입점은 선정 명단이다. 기존 이력을 삭제하거나 소급해서 최종 선정으로 바꾸지 않는다.

## 같은 크리에이터의 채널 통합

마이그레이션 **0027_contact_workflows**는 동일 조직·캠페인·creator_account_id에 하나의 협업 업무를 만든다. 이메일·Instagram 및 복수 발신 계정의 대화는 독립적인 원본 대화로 유지하고 담당자·협의 상태·다음 연락일·내부 메모만 공유한다. 연락 목록은 한 명의 카드에 채널별 링크를 표시하고, 회신이 필요한 채널을 우선 연다. 다른 캠페인과 캠페인이 없는 기존/테스트 연락을 아이디 추정으로 합치지 않는다.

기존 업무 정보 중 가장 최근 편집된 연락 건을 공통 업무의 초기값으로 사용한다. 이전 채널별 메모와 원본 contact_cases의 진행 정보는 보존한다. 원본 메시지·회신 시도의 case_id, 승인·발송 근거는 변경하지 않는다. 공통 정보의 revision으로 동시 편집을 검사한다. 복합 FK와 필수 연결 제약으로 다른 조직·캠페인·크리에이터의 업무에 연결하지 못한다.

## 설치와 검증

DB 소유자로 마이그레이션 0027과 `scripts/outreach-grants.sql`을 적용한다. 배포 전 기존 데이터 백업·행 수/해시를 대조한다. outreach_drafts에는 compose_step만 추가하며 기존 내용에 따라 초기 단계를 복원한다. contact_cases에는 workflow_id만 추가한다. 실행기 0.1.12의 재설치·재연결은 필요 없다.

수신 조회는 활성 화면에서 1분마다 서로 다른 대화 최대 3개를 순환한다. 마지막 묶음이 3개보다 작아도 누락하지 않는다. 목록 필터·검색·담당·테스트 포함은 URL에 보존하고 대화에서 돌아올 때 복원한다. 채널 탭을 바꿔도 같은 협업 업무 정보를 읽는다. 상시 Webhook 수신·푸시, 계약·배송·성과 관리는 이 변경에 포함하지 않는다.

합성 단위 테스트로 순환 조회·채널 묶음·복귀 URL, 폐기형 DB에서 조직 경계·공통 정보·동시 수정·원본 보존, Playwright에서 선정→작성→단계 복원·발송 결과→답장·채널 전환·필터 복원과 320/390/1440 화면을 검증한다. 운영 확인은 읽기로 진행하며 실제 크리에이터에게 새로운 메시지를 보내거나 판정을 바꾸지 않는다.
