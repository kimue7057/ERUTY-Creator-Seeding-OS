# 캠페인 발굴·자동 평가·최종 승인

캠페인 화면에서 플랫폼과 탐색 인원(1–20명)을 선택하고 **발굴·추천 시작**을 누른다. 연결된 실행 PC가 SNS 내부 검색으로 새 후보를 수집하고, 제출된 후보의 저장된 근거를 Codex CLI가 자동 평가한다. SNS 수집과 평가는 순차 실행되며 실행 PC와 Codex 연결이 필요하다. 평가 단계는 새 SNS 방문이나 시청을 하지 않는다.

## 사용 흐름

1. **발굴 요청**: 실제 프로필·최근 콘텐츠·내부 검색의 원본 캡처와 관찰을 저장한다.
2. **자동 평가·선별**: 제품 30, 스타일 20, 타깃 20, 콘텐츠 15, 참여도 10, 협업 5의 기존 배점을 적용한다. 확인 점수 70 이상, 제품 적합도 18 이상, 신뢰도 0.6 이상이며 검증 가능한 원본이 있는 후보만 기본 추천 목록에 올린다. 명시적인 국가·플랫폼·정확한 팔로워 범위 불일치는 제외한다. 부족하거나 불확실한 후보는 정보 부족으로 분리한다. 평가 대기·진행·중단은 별도 상태로 표시한다.
3. **사용자 최종 선정**: 추천 후보 목록에서 상세 패널을 열어 이유, 원본 링크와 미확인 사항을 확인한 후 확인란을 선택하고 최종 선정한다. 보류·제외도 같은 패널에서 기록한다. 선정 결과는 선정 명단에 반영된다. 승인 후에도 이메일·DM을 자동 발송하지 않는다.

미확인 항목은 null로 보존하고 총점을 확정하지 않는다. 확인 점수는 확인된 항목의 합계이며 100점으로 환산하지 않는다. 거주 국가는 시청자 국가의 증거가 아니다. 추천 수는 탐색 인원보다 적을 수 있다. 카드에는 확인 점수와 미확인 항목 수를 함께 표시한다.

평가 입력에는 해시가 일치하는 실제 프로필·콘텐츠 화면 텍스트를 후보별로 최대 40,000자까지 포함하고, 잘린 부분은 표시한다. 화면의 다른 추천·광고·댓글을 해당 크리에이터의 사실로 간주하지 않는다. 이전 수동 과정의 검토 대기 상태는 평가용 입력에서 분리한다. 사람의 승인이 아직 없다는 이유로 적합도 점수를 비우는 단계가 아니며, 실제 자료가 없는 항목은 계속 미확인으로 남긴다.

진행·기록에서 기존 후보는 **기존 후보 자동 평가**로 현재 조건의 평가를 접수할 수 있다. 같은 입력은 중복 접수·중복 과금하지 않는다. 실패한 평가는 **자동 평가 다시 시도**로 명시적으로 재시도하며 최대 3회다. 지출 한도에 도달하면 다른 후보를 계속 실패시키지 않고 30분간 평가 접수를 쉬며, 한도 조정 후 실패 항목 재시도로 즉시 재개할 수 있다. 실행 중단·결과 유실은 실패로 표시하고 자동 유료 재실행하지 않는다.

브리프, 타깃, 계정 정체성 또는 관찰 근거가 바뀌면 이전 추천과 승인은 현재 명단에서 효력을 잃는다. 근거에 제외·재검토 판정이 생기면 최종 승인을 막는다. 추천 점수는 관찰 사실과 구분되며 모든 점수에는 허용된 근거 ID가 필요하다.

## 운영·검증

- 마이그레이션 `0015_campaign_shortlist.sql`은 평가 작업 큐와 범위 제약을 추가한다. 기존 관찰·실행·평가·승인 이력은 변경하지 않는다. 적용 전 DB를 백업하고 `cloud-app-grants.sql`의 제한된 앱 역할 권한을 적용한다.
- `CODEX_DISCOVERY_ENABLED`, `CODEX_AUTOMATIC_DISCOVERY_ENABLED`, `EVALUATION_ENABLED`를 모두 true로 설정하고 최신 `codex-discovery-worker.ts`를 실행한다. 평가는 로그인된 CLI의 기본 모델을 사용하며 별도 API 키가 필요 없다.
- 큐 임대와 작업 결과는 조직·캠페인·계정·입력 해시에 묶인다. 브라우저 탐색과 평가는 실행기당 동시에 하나만 진행한다. 평가는 5분 제한, 임대는 2분이다.
- 원본의 정확한 UTF-8 해시, 해당 후보의 프로필·콘텐츠·내부 검색과 요청 범위를 다시 대조한다. 원본 주소의 핸들 대소문자, 검색어 인코딩과 콘텐츠 주소는 수집 시와 같은 정규화 규칙으로 비교한다. 원본 바이트는 변경하지 않는다.
- 사용자 최종 판정은 `creator_evaluation_reviews`와 감사 로그에 실제 사용자로 추가된다. 한 후보 승인으로 전체 발굴 작업의 브라우저 검토나 다른 후보의 근거 검토 기록을 자동 생성하지 않는다. 이전 수동 검토 경로도 상세 이력에서 유지한다.
- 평가 입력·결과·CLI 이벤트는 `.local/discovery/codex-browser/assessments/`에 비공개로 남는다. 실제 계정 목록·원본·로그·인증 파일은 커밋하거나 배포하지 않는다.

캠페인 화면이 기본 작업 공간이다. 전체 발굴 기록과 개별 평가 이력은 상세 확인용으로 남긴다. 읽기 권한 사용자는 진행과 명단을 조회할 수 있고 요청·판정은 관리자/매니저가 수행한다.

추천 후보 / 선정 명단 / 진행·기록 / 캠페인 설정 탭과 검토함의 직접 연결은 [작업 화면 UX](CAMPAIGN-WORKSPACE-UX.md)를 참고한다. 평가 기준과 최종 인간 판정의 서버 검증은 동일하다.
