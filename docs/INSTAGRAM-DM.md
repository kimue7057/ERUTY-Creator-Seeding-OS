# Instagram 실제 대화 조회와 DM 회신

2026-11-10 사용자 요청으로 실제 발송을 추가한다. 이메일의 기존 분석 → 문장 → 템플릿 → 발송 단계를 유지한다.

## 화면

- **Instagram DM** 메뉴: 연결된 회사 계정 중 발신 계정을 선택 → 대화 불러오기 → 실제 상대·수신 메시지·회신 가능 시각 확인 → 텍스트 작성 → 발신/수신/본문 확인란 → 실제 발송.
- **선정 명단 → 연락하기**: Instagram 채널을 선택하고 기존 분석·문장·미리보기 단계를 진행한다. 마지막 단계에서 발신 계정을 고르고 선정 크리에이터의 아이디와 일치하는 실제 대화를 선택한다. 최종 선정·원본·초안 revision을 발송 직전에 다시 확인한다.
- 대화 목록은 25개씩, 선택한 대화는 최근 메시지 최대 20개를 읽는다. 자동 수신이 아니며 새로고침 버튼으로 확인한다. 수신 메시지는 DB에 복제하지 않고 Meta에서 읽어 화면에 표시한다.
- 직접 회신과 캠페인 초안 발송 모두 별도 불변 발송 기록을 남긴다. 캠페인 발송은 초안 상태와 연결한다. 일반 대화 회신은 캠페인 선정 기록을 만들거나 변경하지 않는다.

## 현재 지원 조건

Unified Login으로 검증된 Instagram 프로페셔널 회사 계정과 `instagram_basic`, `instagram_manage_messages` 권한이 필요하다. 계정 연결과 대화 API 접근 성공은 서로 다르다. Meta의 테스트 역할·일반/고급 접근·검수 상태, 실제 자산 할당, Instagram 메시지 액세스 설정을 충족해야 한다. ERUTY는 이를 우회하지 않는다.

상대가 회사 계정에 먼저 보낸 메시지가 있어야 하며 마지막 수신 후 24시간 이내 회신만 지원한다. 회사가 보낸 메시지는 이 시간을 연장하지 않는다. 크리에이터 아이디로 수신 ID를 추측하지 않고, 실제 발신 계정의 대화에서 얻은 Instagram scoped ID만 사용한다. 새로운 상대에게 먼저 보내는 DM, 첨부파일 발송, 그룹 대화, Instagram Login 전용 토큰, HUMAN_AGENT 연장, Webhooks 자동 수신·읽음 추적은 현재 지원하지 않는다. 앱 내 작성 한도는 1,000자다.

## 서버와 발송 기록

모든 작업은 현재 DB 멤버십과 조직/발신 계정 범위를 검사한다. 조회·회신은 관리자/매니저만 가능하다. 각 조회와 발송 전에 저장된 앱·토큰·현재 Instagram 신원·메시지 권한을 검증한다. 대화는 해당 발신 계정의 `/conversations` edge에서 소유를 확인한 뒤 선택한 scoped ID와 사용자명이 일치해야 한다. 임의 노드 ID로 다른 회사 계정 대화를 읽거나 보낼 수 없다.

시도는 발신·수신·본문·요청 ID와 함께 먼저 DB에 커밋한다. 발송 직전 다시 계정·대화·회신 창·캠페인 승인을 확인한다. `sent`는 Meta가 일치하는 수신 ID와 메시지 ID를 반환했다는 뜻이며 수신·읽음을 보장하지 않는다. 명확한 거절은 `failed`, 네트워크 단절·불명확한 5xx·잘못된 성공 응답·전송 후 저장 실패는 `unknown` 또는 `sending`으로 보존한다. 결과가 불명확한 대화는 새 요청 ID를 사용해도 추가 전송을 차단한다. 자동 재시도·상태 초기화는 제공하지 않는다. 운영자는 실제 Instagram 대화와 공급자 기록을 대조해야 한다. 일반 Send API에 exactly-once 보장을 가정하지 않는다.

토큰·앱 시크릿·원문 Meta 오류·인증 URL은 브라우저/기록/로그에 반환하지 않는다. 실패 기록에는 고정 오류 이름과 숫자 Meta 코드만 보관한다. 입력 확인란은 계정·수신자·내용 변경 시 초기화한다.

## 설치·검증

소유자 DB 권한으로 `0019_instagram_dm`과 `scripts/outreach-grants.sql`을 적용한다. 기존 초안에는 nullable 대화 선택 열을 추가하며, 기존 기록을 수정하지 않는다. 런타임 역할은 새 발송 테이블의 SELECT/INSERT/UPDATE만 부여받는다. 이력 변경·삭제는 DB 트리거로 차단한다.

단위 테스트: 수신 기준 24시간 경계·미래 시각·대화 소유·상대 불일치·공급자 URL 미추종·성공 수신 ID 검증·명확한 거절/결과 불명 구분.
PostgreSQL 통합: 조직/역할 격리·동시 클릭·같은 요청 재사용·새 ID로 불명 전송 재시도 차단·불변 기록·연결 해제·권한 철회·캠페인 선정/개정·상대 일치 확인.
브라우저: 로컬 Meta fixture를 사용한 실제 서버 액션의 대화 조회 → 메시지 → 확인 → 합성 발송 → 새로고침 후 기록 유지와 작은 화면 확인. 합성 테스트는 실제 Meta 전송 성공을 증명하지 않는다. 실제 회사 계정 조회, 테스트 상대의 선행 DM, 승인된 문구의 전송 및 수신 확인을 별도로 기록한다.

공식 근거: [Meta IGUser SDK의 conversations/messages 경로](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/iguser.py), [Meta Instagram API 컬렉션](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api), [공식 메시지 컬렉션 원본](https://github.com/fbsamples/messenger-platform-samples/tree/main/postman). Meta 개발자 문서가 접근 제한 응답을 주는 환경에서는 그 제한을 우회하지 않으며 실제 계정 동작은 별도로 확인한다.
